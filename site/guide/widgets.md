# Widgets

A widget pairs a small native view with a provider that knows when its data changes. Rendering and collection are separate so a slow integration cannot stall the whole bar.

::: warning Pre-alpha status
The native providers below are implemented and unit-tested in the Swift package, but there is no signed app yet and they are not physically validated on hardware. On this website the bar preview uses static sample values; the running app (built from source) reads live local values.
:::

## Built-in items

| Identifier | Default side | Role | Update strategy |
| --- | --- | --- | --- |
| `workspaces` | left | Window-manager workspaces | Manager events or bounded refresh (AeroSpace and yabai adapters delivered; not physically validated) |
| `front-app` | left | Frontmost application | Workspace/application notifications |
| `battery` | right | Charge and power state; click toggles keep-awake | System power notifications |
| `date` | off by default | Local date; click opens the calendar popover with a month grid, navigation, and Date & Time settings link | Emits immediately, then at each day boundary |
| `time` | right | Local time | Emits immediately, then at each minute boundary by default; seconds optional |
| `network` | right | Wi-Fi/network status; click opens the read-only Wi-Fi popover | Network path notifications |
| `volume` | right | Output volume; click opens the volume popover with a slider and mute | Audio notifications |
| `appearance` | off by default | Current light/dark mode (sun or moon); click opens the appearance popover to set the mode and theme family | System appearance notifications |

Both sides are ordered item groups and every supported item can move between them. The native app fills this default bar from built-in providers — no setup questionnaire and no shell polling. Workspace app icons and empty-state visibility are optional settings on `workspaces`.

The date and time are separate items (task 0033). The default `right` group is `battery`, `time`, `network`, `volume`: the time is on at first launch and the date is off. The date can include the weekday and the year, use a day-first order, a custom separator, or a custom pattern; the time can show seconds and use 24-hour, AM/PM, or a custom pattern. Both edit the `widgets.date` and `widgets.time` objects the [configuration reference](../reference/configuration) documents. The legacy combined `clock` item is accepted and migrated to `date`/`time` on load.

While the Mac is charging, the battery item draws a battery-with-bolt symbol: the outline and fill keep the normal label colour for the theme (black on a light bar), and only the bolt is a fixed green, independent of the theme: the same green on Native, Alpine, Gruvbox, Ayu, Dracula, and Tokyo Night. It never takes the family accent, so a purple or blue accent (Dracula, Tokyo Night) cannot make the bolt read as anything but green. The symbol leaves a thin gap around the bolt, which keeps the green legible against the battery fill. The percentage label keeps the normal foreground colour. When charging stops, the bolt and the green are gone.

Clicking the battery item toggles a Caffeine-style keep-awake assertion and shows a cup indicator while it is held. The cup and the charging bolt stay separate: the cup is the keep-awake state, the bolt is the charge state. The cup uses a fixed green pair (light mode: #0B6B3A dark green; dark mode: #7BD88F bright green), independent of the theme accent, so it reads as a distinct keep-awake mark on every family with 3:1 contrast guaranteed against bar backgrounds: the same pair on Native, Alpine, Gruvbox, Ayu, Dracula, and Tokyo Night. The default chip is an opaque `selected` fill that can hide that green, so the cup is audited against the composited chip fill too and, where the green cannot clear 3:1, is stroked with a thin black or white outline (whichever contrasts more with the chip) rather than a shadow. The cup tracks Divot's own assertion only: another app preventing sleep — for example a call holding the microphone and speaker sleep assertions — does not show it while Divot's toggle is off. Keep-awake uses the public IOKit power-assertion API only; quitting the app releases any assertion it holds. Whether the state is remembered across launches is an opt-in setting (default off). When you toggle caffeine, a short message ("Caffeine on" / "Caffeine off") can appear in a small panel just below the battery item; it dismisses itself after about two seconds, ignores mouse clicks, and does not use Notification Center, so Focus and Do Not Disturb do not hide it. You can turn the message off with `keepAwake.showToast` or **Show keep-awake message** in Settings (default on). Remembered state restored at launch does not show the message. This is implemented and unit-tested in the Swift package, not physically validated.

## Failure and unavailable states

A disabled provider removes its observers and cancels outstanding work. A failed provider gets an understandable unavailable state while the rest of the bar keeps working; a late background result from an old configuration or a disabled provider is ignored. A desktop Mac shows a settled no-battery state rather than an error.

## Permissions

The date, time, battery, volume, and frontmost-app items need no special permission themselves. Divot asks macOS for Accessibility once at launch when it is not already granted, because the notched-display menu-bar probe uses it; denying it leaves the rest of the bar running. The network item can optionally display the current Wi-Fi network name (SSID); this feature requires Location permission on macOS and is only requested when the user turns the toggle on. If permission is denied, the Settings row says so and links to the Location Services pane while the bar shows the icon only.

Listing nearby networks in the Wi-Fi popover also needs Location permission, because macOS gates network names on it. Divot does not prompt from the popover: without permission it shows a short message and a button that opens **System Settings → Privacy & Security → Location Services**, rather than an empty list.

## Click behavior

Divot does not mirror the system's menu extras. Each item has one explicit action: the frontmost-app item activates that app; the battery item toggles keep-awake; the appearance item opens an appearance popover to set Divot's own light/dark mode and theme family (it no longer toggles directly) and never changes the macOS system appearance; the date item opens a calendar popover; the time item opens a world clock popover showing your local time and any added world timezones; the network item opens a read-only Wi-Fi popover; and the volume item opens an output-volume popover with a slider and mute.

All four popovers behave the same way: they close on any click outside them (including in another app or on the desktop), on Escape, and on a second click of the same bar item that opened them. Content is left-aligned for readability. They draw the bar's own theme colours, so their text, secondary labels, and links match the bar in light and dark and clear the documented contrast floors. Every family and the native theme paint a solid, opaque popover background with a thin border and rounded corners; family themes use their audited palette, and native uses fixed light/dark hex values to ensure readability. Every popover adopts the bar's light/dark appearance instead of the app-wide one, so popovers always match their bar. This dismissal is implemented and unit-tested in the Swift package; the popover rendering (opacity and background bleed-through) is checked on the packaged app, not claimed here. They share one look: a solid, opaque panel in the active theme's popover colours (light or dark), with an arrow toward the bar item, left-aligned text and links, and one filled highlight for the current choice or today.

The Wi-Fi popover lists the nearby networks with their signal and a lock for secured ones, marks the connected network, and ends with **Open Wi-Fi Settings…**, which opens System Settings › Wi-Fi directly (falling back to the generic Network pane if that link cannot be opened). It is read-only: it never joins a network and never asks for a password. The list has a maximum height of 90% of the screen height, so a long list of networks scrolls rather than growing the popover without bound. Divot scans once each time the popover opens — never on a timer — and the scan runs off the main thread with a timeout, so the popover always settles into a list, an empty state, or an error. This is implemented and unit-tested in the Swift package; the popover on screen is not physically validated yet.

The volume popover has a horizontal slider for the default output with its current percentage, a **Mute** toggle, and a final **Open Sound Settings…** row that opens the Sound pane. Moving the slider changes the output's volume, and the bar item's icon and percentage follow it. It uses public Core Audio only; there is no timer, and while the popover is open it follows changes made elsewhere (a keyboard volume key, another app) through property listeners that are removed when the popover closes. For an output with no settable volume — some HDMI/DisplayPort devices — the slider and mute are disabled and a short note explains why instead of offering a control that cannot do anything. This is implemented and unit-tested in the Swift package; whether the slider actually moves a real output's volume is checked on the packaged app, not claimed here.

The calendar popover shows a month grid with the current month at launch, navigation chevrons to browse months, a **Today** button to jump back to the current month, and an **Open Date & Time Settings…** footer row. Day cells show dates from the displayed month in full opacity and dates from adjacent months in reduced opacity; the current date is highlighted with the theme accent. The layout respects the system's locale and calendar settings for the first weekday (Sunday, Monday, or other) and weekday names. Opening the popover always starts with the current month and updates when midnight passes while the popover is open. This is implemented and unit-tested in the Swift package.

The world clock popover shows the local time with its UTC offset (e.g., "23:16 UTC+7") and the local timezone name, followed by any user-added world timezones. Each timezone row displays its city or region name, the current time in that zone (following your time format and seconds settings), the hour offset from local time (e.g., "5 h ahead", "30 min behind"), a remove control, and a day label (Yesterday/Tomorrow) only when that zone's calendar day differs from your local date. A time scrubber converts at any time of day on the local date: drag the slider, click, or use the arrow keys to move in 15-minute steps, and every row updates to the equivalent time in its zone with the matching day label; a **Now** button resets to the current minute. Each row also carries a small sun or moon marker showing whether that zone is inside the fixed 09:00–18:00 local working window, so a sensible hour to call is visible at a glance. When the timezone list has never been configured, the popover shows three default zones: San Francisco, London, and Singapore (omitting any that match your local zone); once you add or remove a zone, the list is persisted and the defaults no longer appear unless the configuration key is explicitly unset. An **Add timezone…** row with a search field finds IANA identifiers as you type (matching city or region names, e.g., "los" for Los Angeles; press Return to add the selected result or click one to add it); pressing Escape clears the search. Every match is listed, and a zone already in your list is shown disabled and marked **Already added** rather than hidden. The results list grows up to 90% of the screen height and scrolls beyond that, so a broad query never overflows the screen. The zone list fits up to eight rows and scrolls beyond that, so a long list never grows the panel without bound. The last row opens the Date & Time pane. Timezones are persisted in the configuration as an ordered list of IANA identifiers (e.g., `America/Los_Angeles`, `Asia/Tokyo`); duplicates are removed and an unknown identifier is ignored when the popover renders rather than breaking the config. This is implemented and unit-tested in the Swift package.

The appearance popover sets Divot's own **System**/**Light**/**Dark** variant with a horizontal segmented control and the theme family (Native, Gruvbox, Ayu, Dracula, Tokyo Night) as a vertical list of theme options, each showing a colour swatch from that theme's palette and the family name, with the current selection clearly marked, and ends with an **Open Divot Settings…** row that opens Divot's own settings window, not a System Settings pane. Both come from the same configuration fields the Settings window edits — a new family appears here automatically — and a choice applies immediately through the same atomic store, so the popover and the Settings window never disagree; while it is open it also follows a change made in the Settings window or the config file. It changes Divot's own rendering only and never the macOS system appearance. This is implemented and unit-tested in the Swift package; the popover on screen is not physically validated yet.

The Sound pane link still needs validation on the target OS.

## Future script widgets

Scripts are a later milestone. The protocol should have output limits, deadlines, cancellation, and a documented data format. No script API is available yet; do not assume xbar or SketchyBar compatibility.

Scripts will be trusted local programs, not safely sandboxed by a timeout. The first release prioritizes native providers so a normal setup does not continually launch shell processes.
