# Configuration contract · version 2

The app-side parser, validated model, atomic store, migration, and settings surface are implemented (task 0006). Version 2 is the version the native loader accepts. The four theme families and palette application are implemented too (task 0011): `appearance.family` and `appearance.palette` are parsed, persisted, and resolved to semantic tokens that repaint the bar. The website preview and structural checker use these same examples and shapes.

Use UTF-8 JSON at `~/.config/divot/config.json`. Missing file uses native defaults; invalid file preserves the last valid configuration and reports the failing field path. Unknown keys produce actionable diagnostics. File writes from settings are atomic (staged and renamed) and preserve supported user settings; JSON has no comments. The native app reads the file at launch, watches it for external edits, and parses away from the main thread.

Two ordered groups, `left` and `right`, hold the bar's items, and an item appears in exactly one group. Both sides are configurable: add, remove, reorder, or move any supported item. Defaults match the first-launch story, so a missing file or an omitted `widgets` object still produces the full default bar. Appearance sets a theme `family` and a separate `mode`; the family survives appearance changes. Per-item options are namespaced under `widgets`.

Supported items: `workspaces`, `front-app`, `battery`, `network`, `volume`, `clock`. Default left is `workspaces`, `front-app`; default right is `battery`, `clock`, `network`, `volume`. Clock resolution stays minutes unless `widgets.clock.seconds` is enabled. The workspace row's own options are an `adapter` override (`aerospace` or `yabai`), `showEmpty`, `showAppIcons`, `showDetails`, and an optional `maxAppIconsPerWorkspace` cap. Appearance `family` is `native` (default), `gruvbox`, `ayu`, `dracula`, or `tokyo-night`; `mode` is `system`, `dark`, or `light`; the root `accent` defaults to the built-in `#D6F58A`, and while it is left at that default a family uses its own signature accent, while any other value overrides the family. Layout height is 24–40 points (default 32, matched to the camera-housing band), padding 0–24, notch gap 0–32; the native loader reads all three at launch and applies them to the panels. Text size (task 0022) is an optional root `text` object: `size` is 10–20 points (default 14, larger than the original fixed 12 pt) and `font` is an installed family name, or `""` (default) for the system font. Icon and chip sizes are derived from `size` in `DivotCore.BarMetrics.scaled` — the icon is two points larger, the chip one point smaller — so the row stays in proportion as the text grows; the rest of the rhythm (an 8-point gap between items, a 6-point default row inset) is still fixed in `BarMetrics`. A `font` that is not installed falls back to the system font at render time (`DivotCore.BarFontResolver`), never a rejected document. `LayoutConfiguration` takes its default height and padding from `BarMetrics`, and `BarGeometry` / `BarContentPolicy` take their default height from the same value.

Keep-awake (task 0018) is an optional root object, `keepAwake`, rather than a `widgets.battery` option so it stays valid when the battery item is not placed. `remember` (default `false`) opts in to persisting the state across launches; `isActive` (default `false`) is the remembered on/off state and is written only while `remember` is on. Clicking the battery item toggles keep-awake, and the item shows a cup indicator while the assertion is held. A document with no `keepAwake` object launches with keep-awake off.

Menu-bar detection (task 0021) is an optional root object, `menuBar`. On notched hardware the camera housing masks the same top band whether the native bar is hidden or revealed, so `trustAccessibilityProbe` (default `false`) opts in to the permission-gated Accessibility observation of the bar's own on-screen frame to follow reveal/hide. It is off by default because the on-screen heuristic is hardware-sensitive; while off, a notched display holds the top edge and never moves below a bar it cannot confirm. Enable it on a Mac whose Accessibility grant and geometry you have confirmed:

```json
{ "menuBar": { "trustAccessibilityProbe": true } }
```

Custom palette overrides use the same contract: an optional `appearance.palette` object overrides individual semantic color tokens—`foreground`, `background`, `accent`, `selected`, `occupied`, `error`—as six-digit hex, merged over the selected family and variant. `palette.accent` takes precedence over the root `accent`. The parser, store, and theme resolver validate, persist, and apply these overrides; derived chrome roles (muted/disabled text, surface, border, selected label) follow an overridden base so a custom palette stays coherent.

See `examples/default.json`, `examples/focus.json`, `examples/opaque.json`, `examples/custom-palette.json` and the public reference for complete examples. They use the same shape and are validated during web checks; the checker also runs negative cases for unknown tokens, misplaced items, and unknown options, and validates the version 1 migration fixtures under `examples/migrations/`. The starter checker rejects unknown fields/types/ranges and unknown or misplaced items; later replace duplication with generated schema or cross-language contract fixtures.

## Migration and extension

Version 1 was a pre-release draft that hard-coded workspaces on the left and a status-only right array. It never shipped and is superseded by version 2: the native loader migrates `workspaces` into `left`, its options into `widgets.workspaces`, and each `status` identifier into `right` (`DivotCore.ConfigurationParser.migrateV1`, covered by the `examples/migrations/v1-*.json` fixtures). Migrations are explicit; an existing field is never reinterpreted silently, and unknown versions are rejected rather than treated as version 2. Before rewriting a migrated file the store copies the original beside it as `config-v1-backup.json`, so a recoverable original always exists. Add new built-ins only with provider tests, doc changes, and performance evidence. `widgets.workspaces.adapter` accepts `aerospace` and `yabai` (task 0012); the native loader honors it as the user override and `DIVOT_WORKSPACES_ADAPTER` from the environment, while the parser rejects any other value. Future per-display overrides use stable display identity and inherit global defaults. Script settings and API credentials do not belong in committed example files.
