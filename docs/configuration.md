# Configuration contract · version 2

The app-side parser, validated model, atomic store, migration, and settings surface are implemented (task 0006). Version 2 is the version the native loader accepts. The four theme families and palette application are implemented too (task 0011): `appearance.family` and `appearance.palette` are parsed, persisted, and resolved to semantic tokens that repaint the bar. The website preview and structural checker use these same examples and shapes.

Use UTF-8 JSON at `~/.config/divot/config.json`. Missing file uses native defaults; invalid file preserves the last valid configuration and reports the failing field path. Unknown keys produce actionable diagnostics. File writes from settings are atomic (staged and renamed) and preserve supported user settings; JSON has no comments. The native app reads the file at launch, watches it for external edits, and parses away from the main thread.

Two ordered groups, `left` and `right`, hold the bar's items, and an item appears in exactly one group. Both sides are configurable: add, remove, reorder, or move any supported item. Defaults match the first-launch story, so a missing file or an omitted `widgets` object still produces the full default bar. Appearance sets a theme `family` and a separate `mode`; the family survives appearance changes. Per-item options are namespaced under `widgets`.

Supported items: `workspaces`, `front-app`, `battery`, `network`, `volume`, `clock`. Default left is `workspaces`, `front-app`; default right is `battery`, `clock`, `network`, `volume`. Clock resolution stays minutes unless `widgets.clock.seconds` is enabled. The volume item shows percentage and muted state by default; both can be toggled off with `widgets.volume.showVolumePercent` and `widgets.volume.showVolumeMuted` (both default `true`), leaving only the icon when both are off. The workspace row's own options are an `adapter` override (`aerospace` or `yabai`), `showEmpty`, `showAppIcons`, `showDetails`, and an optional `maxAppIconsPerWorkspace` cap. Appearance `family` is `native` (default), `gruvbox`, `ayu`, `dracula`, or `tokyo-night`; `mode` is `system`, `dark`, or `light`; the root `accent` defaults to the built-in `#D6F58A`, and while it is left at that default a family uses its own signature accent, while any other value overrides the family. Layout height is 24–40 points (default 32, matched to the camera-housing band), padding 0–24; the native loader reads these at launch and applies them to the panels. On notched displays the bar hugs the notch with zero padding and the color extends 6 points into the notch area to cover the gap and corners (#0028). Text size (task 0022) is an optional root `text` object: `size` is 10–20 points (default 14, larger than the original fixed 12 pt) and `font` is an installed family name, or `""` (default) for the system font. Icon and chip sizes are derived from `size` in `DivotCore.BarMetrics.scaled` — the icon is two points larger, the chip one point smaller — so the row stays in proportion as the text grows; the rest of the rhythm (an 8-point gap between items, a 6-point default row inset) is still fixed in `BarMetrics`. A `font` that is not installed falls back to the system font at render time (`DivotCore.BarFontResolver`), never a rejected document. `LayoutConfiguration` takes its default height and padding from `BarMetrics`, and `BarGeometry` / `BarContentPolicy` take their default height from the same value.

Keep-awake (task 0018) is an optional root object, `keepAwake`, rather than a `widgets.battery` option so it stays valid when the battery item is not placed. `remember` (default `false`) opts in to persisting the state across launches; `isActive` (default `false`) is the remembered on/off state and is written only while `remember` is on. Clicking the battery item toggles keep-awake, and the item shows a cup indicator while the assertion is held. A document with no `keepAwake` object launches with keep-awake off.

The optional app icon (task 0024) is a root boolean, `showAppIcon` (default `false`), rather than a `widgets` option because it decorates the left group instead of a single item. When on, the landing-page mark (`site/public/mark.svg`, shipped as the template `menubar-mark.pdf`) sits at the start of the left group, before the workspaces; clicking it opens the Divot settings window through the same opener as the menu and menu-bar items. It is a template image tinted with the bar's foreground, so one asset follows light and dark, and it scales with the configured `appIconSize` (default 16 pt, matching the status icon size). Toggling it in Settings shows or hides it live and survives a relaunch.

The workspace occupancy markers (task 0026) are two root booleans, `showOccupiedDot` and `showEmptyDot` (both default `true`), rather than `widgets.workspaces` options because they change only the marker drawing in the workspace bar view and not the workspace feed. The filled dot marks an occupied non-focused workspace and the hollow ring marks an empty one (the unknown ring has no toggle and stays as the honest "could not inspect" cue); hiding either leaves the workspace name and the focused highlight, so a workspace stays identifiable. Settings has a matching toggle for each, and toggling one updates the bar live and survives a relaunch.

The flat bar chrome (task 0025) is an optional root boolean, `bottomShadow` (default `false`), rather than a `widgets` option because it changes only the panel chrome. The bar draws a single flat colour from the left screen edge to the right with square corners and no highlight, bevel, or gradient — the chips are flat too. When `bottomShadow` is on, the panel extends a few points below the bar and draws a soft gradient, so the shadow runs along the bottom edge only and never rims the other edges; it is off by default so the first-launch bar has no shadow. Settings has a matching toggle, and toggling it rebuilds the bar live and survives a relaunch.

Chip shape and opacity are root fields (tasks 0030, 0047, 0052). `chipStyle` (default `false`) draws each item in its own rounded chip. `chipOpacity` (0–100, default `0`) fades the background of every chip on the bar — the workspace chips and the right-side status-item chips alike — so `100` matches the bar background and leaves only the content. With `chipStyle` off the workspace chips draw no background at all, so the focused workspace is shown by the semibold weight rather than a box, matching the right-side items. `appIconSize` (8–24 pt, default 16, the status icon size) sets the point size of the app icons drawn on the left: the per-workspace app icons and the Divot mark. Settings has a slider for the opacity and the app icon size, and changes rebuild the bar live and survive a relaunch.

Menu-bar detection is an optional root object, `menuBar`. When the native bar is auto-hidden, macOS reveals it as the pointer reaches the top edge of a display. `moveBelowOnCursorReveal` (default `true`) follows that directly: while the pointer is in a display's top strip Divot sits below the native bar, and when it leaves Divot returns to the top edge. The pointer observation is event-driven (a mouse-moved monitor, no polling) and is decided per display; a notch-free display's own `visibleFrame` cross-checks it, so a reading that disagrees with the geometry is corrected rather than followed.

On notched hardware the camera housing masks the same top band whether the bar is hidden or revealed, so geometry alone cannot decide it. `trustAccessibilityProbe` (default `false`) additionally opts in to the permission-gated Accessibility observation of the bar's own on-screen frame; it is off by default because that heuristic is hardware-sensitive. When it is on it decides the masked case, with the cursor observation as the fallback beneath it. For a Mac where the cursor reveal does not line up, `alwaysBelow` (default `false`) keeps Divot below the native bar at all times:

```json
{ "menuBar": { "moveBelowOnCursorReveal": true, "alwaysBelow": false, "trustAccessibilityProbe": false } }
```

Menu-bar settings are in the Settings window and persist through the store; the cursor reveal behaviour is off when its toggle is off, and the slide respects Reduce Motion.

Custom palette overrides use the same contract: an optional `appearance.palette` object overrides individual semantic color tokens—`foreground`, `background`, `accent`, `selected`, `occupied`, `error`—as six-digit hex, merged over the selected family and variant. `palette.accent` takes precedence over the root `accent`. The parser, store, and theme resolver validate, persist, and apply these overrides; derived chrome roles (muted/disabled text, surface, border, selected label) follow an overridden base so a custom palette stays coherent.

See `examples/default.json`, `examples/focus.json`, `examples/opaque.json`, `examples/custom-palette.json`, `examples/keep-awake.json`, and `examples/app-icon.json` and the public reference for complete examples. They use the same shape and are validated during web checks; the checker also runs negative cases for unknown tokens, misplaced items, and unknown options, and validates the version 1 migration fixtures under `examples/migrations/`. The starter checker rejects unknown fields/types/ranges and unknown or misplaced items; later replace duplication with generated schema or cross-language contract fixtures.

## Migration and extension

Version 1 was a pre-release draft that hard-coded workspaces on the left and a status-only right array. It never shipped and is superseded by version 2: the native loader migrates `workspaces` into `left`, its options into `widgets.workspaces`, and each `status` identifier into `right` (`DivotCore.ConfigurationParser.migrateV1`, covered by the `examples/migrations/v1-*.json` fixtures). Migrations are explicit; an existing field is never reinterpreted silently, and unknown versions are rejected rather than treated as version 2. Before rewriting a migrated file the store copies the original beside it as `config-v1-backup.json`, so a recoverable original always exists. Add new built-ins only with provider tests, doc changes, and performance evidence. `widgets.workspaces.adapter` accepts `aerospace` and `yabai` (task 0012); the native loader honors it as the user override and `DIVOT_WORKSPACES_ADAPTER` from the environment, while the parser rejects any other value. Future per-display overrides use stable display identity and inherit global defaults. Script settings and API credentials do not belong in committed example files.
