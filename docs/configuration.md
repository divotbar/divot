# Configuration contract · version 2

The app-side parser, validated model, atomic store, migration, and settings surface are implemented (task 0006). Version 2 is the version the native loader accepts. The four theme families and palette application are implemented too (task 0011): `appearance.family` and `appearance.palette` are parsed, persisted, and resolved to semantic tokens that repaint the bar. The website preview and structural checker use these same examples and shapes.

Use UTF-8 JSON at `~/.config/divot/config.json`. Missing file uses native defaults; invalid file preserves the last valid configuration and reports the failing field path. Unknown keys produce actionable diagnostics. File writes from settings are atomic (staged and renamed) and preserve supported user settings; JSON has no comments. The native app reads the file at launch, watches it for external edits, and parses away from the main thread.

Two ordered groups, `left` and `right`, hold the bar's items, and an item appears in exactly one group. Both sides are configurable: add, remove, reorder, or move any supported item. Defaults match the first-launch story, so a missing file or an omitted `widgets` object still produces the full default bar. Appearance sets a theme `family` and a separate `mode`; the family survives appearance changes. Per-item options are namespaced under `widgets`.

Supported items: `workspaces`, `front-app`, `battery`, `network`, `volume`, `date`, `time`, `appearance`. The `appearance` item shows the current light/dark mode and toggles Divot's own rendering (never the macOS system appearance). Default left is `workspaces`, `front-app`; default right is `battery`, `time`, `network`, `volume`. The legacy combined `clock` item is accepted and migrated to `date`/`time` (#0033); time resolution stays minutes unless `widgets.time.seconds` is enabled. The volume item shows percentage and muted state by default; both can be toggled off with `widgets.volume.showVolumePercent` and `widgets.volume.showVolumeMuted` (both default `true`), leaving only the icon when both are off. The workspace row's own options are an `adapter` override (`aerospace` or `yabai`), `showEmpty`, `showAppIcons`, `showDetails`, and an optional `maxAppIconsPerWorkspace` cap. Appearance `family` is `native` (default), `gruvbox`, `ayu`, `dracula`, or `tokyo-night`; `mode` is `system`, `dark`, or `light`; the root `accent` defaults to the built-in `#D6F58A`, and while it is left at that default a family uses its own signature accent, while any other value overrides the family. Layout height is 24–40 points (stored default 32; when left at the default the app resolves the row height per display from the native menu-bar band — the camera-housing top on a notched display, the native menu-bar height on a notch-free one — so the row lines up with the system bar, with 32 as the fallback when the band is unknown, #0045), padding 0–24, right item spacing 0–32 (default 8), and left item spacing 0–32 (default 8); the native loader reads these at launch and applies them to the panels. On notched displays the bar hugs the notch with zero padding and the color extends 6 points into the notch area to cover the gap and corners (#0028). Text size (task 0022) is an optional root `text` object: `size` is 10–20 points (default 14, larger than the original fixed 12 pt) and `font` is an installed family name, or `""` (default) for the system font. Icon and chip sizes are derived from `size` in `DivotCore.BarMetrics.scaled` — the icon is two points larger, the chip one point smaller — so the row stays in proportion as the text grows. The battery, network and volume symbols are drawn at that icon size, so the three read at the native menu-bar symbol size (16 pt by default) and scale with the text setting, while the other items keep the compact square status-icon box (#0057). Item spacing is a layout setting (#0060): the right group uses `rightItemSpacing` and the left group uses `leftItemSpacing`, both defaulting to the pre-#0054 uniform 8 points, and the gap immediately before the front-app item uses the left spacing too. A fixed 17-point inset between the rightmost item and the screen edge (`BarMetrics.rightEdgeInset`) keeps the camera-in-use indicator clear of content; the 6-point default row inset stays fixed in `BarMetrics`. A `font` that is not installed falls back to the system font at render time (`DivotCore.BarFontResolver`), never a rejected document. `LayoutConfiguration` takes its default height and padding from `BarMetrics`, and `BarGeometry` / `BarContentPolicy` take their default height from the same value.

Keep-awake (task 0018) is an optional root object, `keepAwake`, rather than a `widgets.battery` option so it stays valid when the battery item is not placed. `remember` (default `false`) opts in to persisting the state across launches; `isActive` (default `false`) is the remembered on/off state and is written only while `remember` is on. Clicking the battery item toggles keep-awake, and the item shows a cup indicator while the assertion is held. The cup is driven by Divot's own assertion, never by system-wide sleep prevention, so another app keeping the Mac awake does not light it while Divot's toggle is off. A document with no `keepAwake` object launches with keep-awake off.

The optional app icon (task 0024) is a root boolean, `showAppIcon` (default `false`), rather than a `widgets` option because it decorates the left group instead of a single item. When on, the landing-page mark (`site/public/mark.svg`, shipped as the template `menubar-mark.pdf`) sits at the start of the left group, before the workspaces; clicking it opens the Divot settings window through the same opener as the menu and menu-bar items. It is a template image tinted with the bar's foreground, so one asset follows light and dark, and it scales with the configured `appIconSize` (default 16 pt, matching the status icon size). Toggling it in Settings shows or hides it live and survives a relaunch.

The workspace occupancy markers (task 0026) are two root booleans, `showOccupiedDot` and `showEmptyDot` (both default `true`), rather than `widgets.workspaces` options because they change only the marker drawing in the workspace bar view and not the workspace feed. The filled dot marks an occupied non-focused workspace and the hollow ring marks an empty one (the unknown ring has no toggle and stays as the honest "could not inspect" cue); hiding either leaves the workspace name and the focused highlight, so a workspace stays identifiable. Settings has a matching toggle for each, and toggling one updates the bar live and survives a relaunch.

The flat bar chrome (task 0025) is an optional root boolean, `bottomShadow` (default `false`), rather than a `widgets` option because it changes only the panel chrome. The bar draws a single flat colour from the left screen edge to the right with square corners and no highlight, bevel, or gradient — the chips are flat too. When `bottomShadow` is on, the panel extends a few points below the bar and draws a soft gradient, so the shadow runs along the bottom edge only and never rims the other edges; it is off by default so the first-launch bar has no shadow. Settings has a matching toggle, and toggling it rebuilds the bar live and survives a relaunch.

Chip shape and opacity are root fields (tasks 0030, 0047, 0052, 0059). `chipStyle` (default `false`) draws each right-side item in its own rounded chip and gives the selected workspace the same chip; unselected workspaces stay a plain number plus app icons with no background, border, or padding. `chipOpacity` (0–100, default `0`) fades the background of every chip that is drawn — the selected workspace chip and the right-side status-item chips alike — so `100` matches the bar background and leaves only the content. With `chipStyle` off no workspace chip is drawn at all, so the focused workspace is shown by the semibold weight rather than a box, matching the right-side items. `appIconSize` (8–24 pt, default 16, the status icon size) sets the point size of the app icons drawn on the left: the per-workspace app icons and the Divot mark. Settings has a slider for the opacity and the app icon size, and changes rebuild the bar live and survive a relaunch.

Menu-bar detection is an optional root object, `menuBar`. When the native bar is auto-hidden, macOS reveals it as the pointer reaches the top edge of a display. `moveBelowOnCursorReveal` (default `true`) follows that directly: while the pointer is in a display's top strip Divot sits below the native bar, and when it leaves Divot returns to the top edge. The pointer observation is event-driven (a mouse-moved monitor, no polling) and is decided per display; a notch-free display's own `visibleFrame` cross-checks it, so a reading that disagrees with the geometry is corrected rather than followed.

On notched hardware the camera housing masks the same top band whether the bar is hidden or revealed, so geometry alone cannot decide it. `trustAccessibilityProbe` (default `false`) additionally opts in to the permission-gated Accessibility observation of the bar's own on-screen frame; it is off by default because that heuristic is hardware-sensitive. When it is on it decides the masked case, with the cursor observation as the fallback beneath it. For a Mac where the cursor reveal does not line up, `alwaysBelow` (default `false`) keeps Divot below the native bar at all times:

```json
{ "menuBar": { "moveBelowOnCursorReveal": true, "alwaysBelow": false, "trustAccessibilityProbe": false } }
```

Menu-bar settings are in the Settings window and persist through the store; the cursor reveal behaviour is off when its toggle is off, and the slide respects Reduce Motion.

Custom palette overrides use the same contract: an optional `appearance.palette` object overrides individual semantic color tokens—`foreground`, `background`, `accent`, `selected`, `occupied`, `error`—as six-digit hex, merged over the selected family and variant. `palette.accent` takes precedence over the root `accent`. The parser, store, and theme resolver validate, persist, and apply these overrides; derived chrome roles (muted/disabled text, surface, border, selected label) follow an overridden base so a custom palette stays coherent.

See `examples/default.json`, `examples/focus.json`, `examples/opaque.json`, `examples/custom-palette.json`, `examples/keep-awake.json`, and `examples/app-icon.json` and the public reference for complete examples. They use the same shape and are validated during web checks; the checker also runs negative cases for unknown tokens, misplaced items, and unknown options, and validates the version 1 migration fixtures under `examples/migrations/`. The starter checker rejects unknown fields/types/ranges and unknown or misplaced items; later replace duplication with generated schema or cross-language contract fixtures.

## Command-line interface

The `divot` binary has a `config` subcommand for agents and scripts. It reads and writes the same `~/.config/divot/config.json` document through the same `ConfigurationParser` and `ConfigurationStore` the app and Settings window use, so a value the CLI accepts loads natively and a value it rejects keeps the last good file. Writes are atomic (staged and renamed). The running app watches that file's directory, so a `divot config set` takes effect without restarting the app: a valid edit is applied, and an invalid one is refused and the app keeps the last valid configuration. The command talks to the file directly: there is no daemon, no network API, and no runtime dependency.

```bash
divot config schema --json          # every setting: key, type, range, default, one-line description
divot config show --json            # the effective document
divot config get widgets.time.seconds
divot config set widgets.time.seconds true
divot config set layout.height 30 --dry-run --diff
divot config unset keepAwake.remember
divot config validate --file ./config.json
divot items list --json
divot items add date --side left --at 0
divot items move workspaces --side right
divot theme set gruvbox --mode dark
divot status --json                 # app, permissions, workspace adapter, config
```

Keys are dotted JSON paths (`appearance.mode`, `layout.leftItemSpacing`, `widgets.workspaces.showAppIcons`, `menuBar.alwaysBelow`). `schema --json` is generated from `DivotCore.ConfigurationSchema`, the registry wired to the same `DivotConfiguration` fields the loader, store, and Settings UI edit; a test fails if the model serializes a setting with no schema entry, so the documented list cannot go stale. On an invalid edit the CLI names the field and the valid values (`appearance.family: expected native | gruvbox | ayu | dracula | tokyo-night`, `layout.height: expected 24–40`).

`set` validates before it writes; `--dry-run` validates without touching the file and `--diff` shows the changed lines. `unset` restores the setting's declared default, which removes it from the document when the default is omitted. `validate` checks the default file (a missing file is the valid first-launch defaults) or the path passed to `--file`. Exit codes are stable: `0` success, `1` an invalid value or file, `2` a usage error. Use `divot config schema` as the source of truth for what can be set; the corresponding values all live in the versioned contract above.

`divot status --json` is the read-only diagnostics path for an agent or a person. It reports the app version, whether a Divot app instance is running, the Accessibility and Location permission readings, the detected workspace adapter (AeroSpace or yabai, with every supported manager found and where the choice came from), and the config path with its current validity and migration state. The command never prompts for or grants a permission: a missing Accessibility or Location grant is reported with the System Settings pane to open (`Privacy & Security › Accessibility`, `Privacy & Security › Location Services`), and an invalid config is listed as a problem alongside the message that the running app keeps the last valid configuration. It launches no app and writes nothing. Exit codes: `0` for a successful reading, `2` for a usage error.

The `items` and `theme` subcommands are thin, task-shaped wrappers over the same `left`/`right` and `appearance` fields, for the two edits users ask for most. `divot items list|add|remove|move` reads and writes the ordered groups: `add` appends to the right unless `--side` says otherwise, `move` keeps the item's current side unless `--side` is given, `--at` names a zero-based slot, and removing an item also clears its per-item options so the document stays valid. An unknown or legacy (`clock`) spelling, adding an item that is already placed, and an `--at` outside the destination group are refused. `divot theme set <family> [--mode system|dark|light]` validates through the same `ConfigurationSchema` as `divot config set appearance.family`/`appearance.mode` and keeps the current mode when `--mode` is omitted. Both write atomically through `ConfigurationStore` and use the same exit codes as `config`: `0` success, `1` invalid item/value or file, `2` usage error. The public guide's `site/guide/ai-setup.md` page carries a copy-pasteable "set up Divot with your AI" prompt built on `divot config schema --json` and `divot status --json`.

## Migration and extension

Version 1 was a pre-release draft that hard-coded workspaces on the left and a status-only right array. It never shipped and is superseded by version 2: the native loader migrates `workspaces` into `left`, its options into `widgets.workspaces`, and each `status` identifier into `right` (`DivotCore.ConfigurationParser.migrateV1`, covered by the `examples/migrations/v1-*.json` fixtures). Migrations are explicit; an existing field is never reinterpreted silently, and unknown versions are rejected rather than treated as version 2. Before rewriting a migrated file the store copies the original beside it as `config-v1-backup.json`, so a recoverable original always exists. Add new built-ins only with provider tests, doc changes, and performance evidence. `widgets.workspaces.adapter` accepts `aerospace` and `yabai` (task 0012); the native loader honors it as the user override and `DIVOT_WORKSPACES_ADAPTER` from the environment, while the parser rejects any other value. Future per-display overrides use stable display identity and inherit global defaults. Script settings and API credentials do not belong in committed example files.
